Set up the real Gmail connection — free, one-time, no card  ▾
  1. Google Cloud Console — go to console.cloud.google.com, sign in with the Google account that owns the test inbox, and create a project called SubSleuth. No billing, no card.
  2. Enable the Gmail API — in that project, open APIs & Services → Library, search Gmail API, and click Enable.
  3. Consent screen — APIs & Services → OAuth consent screen: choose External, app name SubSleuth, add your email, and under Test users add the exact Gmail address you'll test with.
  4. Create the Client ID — Credentials → Create Credentials → OAuth client ID → Web application. Under Authorised redirect URIs add this app's own address, exactly as shown here: … — Google must send the sign-in result back to this page itself, not to the Muse library page: the result arrives in the address bar of the page it returns to, and this app can only read its own. (If you earlier added the library address, it can stay — it just isn't the one used.)
  5. Nothing to paste — your Client ID is already built into this copy of the app (shown locked below). It is only ever sent to Google's sign-in page.
  6. Connect & test — press Connect Gmail above. Sign-in opens in a new tab; approve read-only access there, and Google returns that tab to this app — the scan then starts on its own and the results open in that tab. Pick your own inbox for the strongest demo, or a spare inbox if you'd rather keep your main one private.
Privacy, plainly: the scope is gmail.readonly — SubSleuth can read, never send, delete or change anything. Email content is fetched straight from Google to this browser tab and parsed here. Close the tab and it's gone. Never put your Client ID or inbox contents in the demo video or a public repo.

How it works

One focused job, done well — the way the LaunchPad guide asks for it. Find the money first, add nothing until that works.

01 — SEARCH

It searches like a human would

Queries Gmail for receipts, renewals, trials and payment confirmations from known billing senders — not your whole inbox, just the money trail.

02 — PARSE

Prices & dates, extracted here

A service dictionary matches each sender, pulls the amount and billing cycle, and works out the next renewal. Every result keeps its evidence email so you can check it.

03 — ACT

Total, calendar, cancel link

You get the monthly and yearly total, what's renewing soon, what looks forgotten, and a direct manage/cancel link for every subscription.

Straight answers

Does sample mode prove it works?

No — and the app says so. Sample mode proves the parsing, maths and interface. The proof is the real Gmail test: connect an inbox you own (yours or a spare) using the setup above and it finds real subscriptions live. That's the test to run before recording the demo.

What are the honest limits?

It only finds subscriptions that email you — app-store billing through Apple/Google bundles several services into one receipt, cash or bank-only payments leave no email, and a brand-new service not yet in the dictionary can be missed. Yearly renewals are inferred from the last charge. Every result shows its evidence email so a miss or a wrong date is easy to spot.

What was built, and with what?

Built fresh for LaunchPad Hacks (deadline Fri 4 Dec 2026, 11:00pm Lagos). Plain HTML, CSS and JavaScript in one page; Gmail API + Google Identity Services for the read-only connection; no framework, no backend, no database.
